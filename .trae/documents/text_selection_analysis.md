# 划词功能用户体验与优化分析计划

## 一、 当前状态分析 (Current State Analysis)
目前项目的划词功能通过**系统级全局鼠标 Hook**实现：
- **监听与检测**：通过 Windows API 拦截鼠标左键的按下与释放，计算距离和时间，判定是否为划词（拖拽/双击/三击）。
- **文本捕获**：备份当前剪贴板 -> 模拟 `Ctrl+C` -> 轮询等待剪贴板更新 -> 获取文本 -> 恢复剪贴板内容。
- **UI 与交互**：在获取文本后，在前端计算坐标并弹出悬浮工具栏，提供“翻译”、“解释”、“复制”功能。
- **状态管理**：通过设置页面可全局开启/关闭，并支持修改翻译和解释的 Prompt 模板。

---

## 二、 不合理的点 (Unreasonable Points)
站在用户的实际使用场景，当前机制存在以下痛点：
1. **侵入性过强（误触率极高）**
   - 用户在绘图软件（如 PS/Figma）、玩游戏、或者仅仅是拖拽窗口/文件时，极易触发判定并导致频繁弹窗，打断用户心流。
2. **模拟 `Ctrl+C` 的副作用明显**
   - 备份与恢复剪贴板会污染用户的剪贴板历史记录工具（如 Win+V, Ditto）。
   - 如果此时用户刚好复制了体积巨大的文件或高清图片，备份与恢复会造成明显的系统卡顿。
   - 部分安全软件或密码管理器会拦截模拟按键，导致失效。
3. **缺乏反馈的延迟感**
   - 依赖轮询等待剪贴板更新，导致划词后工具栏弹出存在肉眼可见的延迟感。

---

## 三、 需要优化的点 (Areas for Optimization)
1. **增加黑名单机制（应用级过滤）**
   - 允许用户配置特定软件进程下不触发划词（例如：游戏、设计软件等）。目前代码仅简单过滤了终端环境，覆盖面不够。
2. **优化触发条件（防误触机制）**
   - 增加**辅助键触发**选项：允许设定为 `Alt + 划词` 或 `Ctrl + 划词` 才弹出工具栏。
   - 增加**渐进式交互**：划词后先展示一个极小的半透明 Icon，鼠标悬停时才展开完整工具栏，避免直接遮挡视野。
3. **弹窗位置智能化**
   - 确保弹窗不遮挡选中的文本本身，可根据屏幕边缘自动调整向上或向下弹出。
4. **静默化剪贴板操作**
   - 探索绕过剪贴板历史记录的 API 方案，或增加选项让用户选择是否“恢复剪贴板”。

---

## 四、 需要添加的点 (Features to Add)
1. **自定义快捷指令（Custom Prompts）**
   - 打破写死的“翻译”、“解释”，允许用户在设置中自定义快捷动作（如“总结”、“语法纠正”、“代码注释”），并在工具栏动态展示。
2. **连续对话与窗口固定（Pin Window）**
   - 提供一个“图钉”按钮，允许用户将 AI 结果窗口固定在屏幕边缘。
   - 在弹窗底部加入输入框，允许用户针对选中内容进行连续追问。
3. **快捷发送到主对话**
   - 增加一个“带入主窗口”的按钮，点击后将选中文本作为上下文，直接跳转唤起主程序的对话框。
4. **外观与个性化设置**
   - 允许调整悬浮工具栏的大小、字体和深浅色主题。

---

## 五、 拟定实施步骤 (Proposed Implementation Steps)
如果需要执行上述优化，建议按照以下阶段进行：

### 第一阶段：防误触与基础体验优化（优先级：高）
1. **增加辅助键触发**：在设置页（`SelectionSettings.vue`）和后端监听（`mouse_listener.rs`）中增加 `Alt` / `Ctrl` 键组合触发逻辑。
2. **渐进式弹窗交互**：修改 `selection_toolbar/App.vue`，实现先显示小 Icon，Hover 后展开的功能。

### 第二阶段：可玩性拓展（优先级：中）
1. **自定义动作引擎**：重构设置页和前端工具栏，支持动态增删改查划词动作（Action），替代目前硬编码的 Translate / Explain。
2. **主窗口联动**：增加将选中文本发送至主应用窗口进行深度对话的 IPC 通信机制。

### 第三阶段：底层捕获机制重构（优先级：低）
1. **黑名单进程管理**：实现获取当前前台窗口进程名，比对黑名单跳过检测的功能。
2. **剪贴板优化**：研究 Windows Accessibility API 或特定 Clipboard Format 以取代模拟 `Ctrl+C`。

---
**假设与决定**：
- 假设用户期望的是一个类似 Youdao 词典或 Bob 的非侵入式划词体验。
- 决定先从前端交互和辅助键防误触入手，因为底层系统 API 的重构风险较高且耗时。
