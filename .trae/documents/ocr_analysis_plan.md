# 截图文字识别功能优缺点分析及优化计划

## 1. 当前状态分析 (Current State Analysis)
项目目前的截图文字识别（OCR）采用了双引擎架构，分别通过 Windows 系统原生 API (`NativeOcr`) 和基于 PaddleOCR 的 Rust 库 (`ocr-rs`) 来实现文字提取。核心流程由前端捕获截图，转换为 Base64 编码，通过 Tauri IPC 传递给后端，后端解析识别后将坐标和文本返回前端渲染。

### 优点 (Pros)
- **纯本地离线执行**：不依赖云端服务，隐私安全性极高。
- **高可用双引擎**：
  - **Windows Native**：调用系统级 API，执行速度快。为了弥补原生 API 的不足，代码中内置了强大的**多策略图像预处理**（包括 Lanczos3 放大、自适应二值化、对比度拉伸）和中英文空格智能清理，极大地提升了复杂背景的识别准确率。
  - **ocr-rs**：基于 PP-OCRv5 轻量级模型，对于手写体、倾斜文字和复杂场景的识别准确率极高，并为 macOS/Linux 等平台的跨平台支持奠定了基础。

### 缺点 (Cons)
- **Windows 引擎性能与平台限制**：仅支持 Windows 10/11 平台。目前采取了高达 9 次的并发尝试（原图、增强图、轻度增强图 × 3种语言）来“暴力”求取最优解，在低配机器上可能会导致较高的 CPU 瞬时开销和响应延迟。同时强依赖系统中是否安装了对应的语言包。
- **ocr-rs 引擎排版缺失**：相比于原生引擎，`ocr_rs_engine.rs` 仅将每个检测框直接转为一个段落返回，**缺失了基于空间位置（如相近 Y 坐标）的段落合并功能**，导致最终呈现的排版断行严重，阅读体验较差。且模型推理 CPU 占用较高。
- **传输性能损耗**：前后端图片数据使用 Base64 字符串传输，相比直接传输二进制字节流，存在约 33% 的体积膨胀和额外的编解码耗时。
- **代码冗余**：代码库中同时存在 `ocr_rs_engine.rs` 与 `paddle_ocr.rs` 两套极其相似的模型推理实现，增加了后续维护成本。

## 2. 改进计划 (Proposed Changes)
若需要进一步优化 OCR 功能，建议推进以下修复和提升：

### 阶段 1：核心逻辑与排版优化
- **优化 ocr-rs 的段落合并逻辑**
  - **涉及文件**：`src-tauri/src/services/ocr_rs_engine.rs`
  - **方案**：引入 `paddle_ocr.rs` 中的 `merge_lines_to_paragraphs` 算法，将 Y 坐标相近的文本行合并为同一个 `OcrParagraph`，恢复自然的阅读排版。
- **清理冗余的 OCR 实现**
  - **涉及文件**：删除 `src-tauri/src/services/paddle_ocr.rs`
  - **方案**：梳理并移除旧版的 `paddle_ocr.rs` 代码，统一通过 `ocr_rs_engine.rs` 维护基于模型的离线识别功能。

### 阶段 2：性能优化
- **优化 Windows Native 的多策略评分机制**
  - **涉及文件**：`src-tauri/src/services/native_ocr.rs`
  - **方案**：引入“快速路径 (Fast Path)”。优先使用原图或轻度增强图进行识别，若结果置信度或评分超过安全阈值，则直接返回；仅在效果不佳时，再开启耗时的深度增强重试，以降低平均 CPU 开销。
- **将 Base64 IPC 传输替换为 Raw Bytes**
  - **涉及文件**：前端相关调用与后端 `src-tauri/src/ui/commands.rs` -> `recognize_image_ocr`
  - **方案**：改用 Tauri 提供的二进制传输机制传递截图数据，避免 Base64 编解码损耗。

## 3. 假设与决策 (Assumptions & Decisions)
- 假设 `paddle_ocr.rs` 属于历史遗留代码，当前并未被 `commands.rs` 作为主逻辑使用，可安全清理。
- 假设体验（排版合理性、降低卡顿）优于极致的识别耗时，因此阶段 1 的段落合并将被列为首要优化项。

## 4. 验证步骤 (Verification steps)
1. 在 `ocr-rs` 引擎下运行项目并截取多行文字的图片，确认输出结果是否正确分段（而不是每行文字作为一个独立段落）。
2. 在 `Windows Native` 引擎下识别清晰文字，查看控制台日志，确认系统是否触发了快速返回策略而没有执行多余的预处理。
3. 检查控制台中是否有关于 Base64 转换相关的错误或警告，验证底层二进制传输的兼容性。
