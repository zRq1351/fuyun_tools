# 01 - 项目整体架构

## 1. 项目定位

`fuyun_tools` 是基于 Tauri 2 的桌面效率工具，核心是将系统级输入能力与多窗口 UI 结合，形成四条主功能链路：

1. 文字剪贴板管理与回填。
2. 图片剪贴板管理、预览、分类与标签。
3. Windows 划词后触发 AI 翻译/解释（流式结果窗口）。
4. Windows 截图/OCR 与录屏（含录屏胶囊）。

## 2. 架构分层

### 2.1 前端层（`src/`）

- 技术栈：`Vue 3 + Vite + Element Plus`。
- 形态：多页面应用（MPA），每个窗口对应一个独立入口 HTML。
- 主要职责：
  - 渲染各功能窗口（剪贴板、设置、截图、结果、录屏胶囊等）。
  - 通过 `invoke` 调用 Rust 命令。
  - 通过事件总线监听后端状态变化（例如历史更新、录屏进度、冲突提示）。

### 2.2 后端层（`src-tauri/src/`）

- 技术栈：`Rust + Tauri 2 + sqlx/sqlite`。
- 主要职责：
  - 注册全局快捷键、托盘菜单、窗口生命周期。
  - 监听系统剪贴板/鼠标键盘并进行系统交互。
  - 管理文本与图片历史、分类、置顶、分页读取。
  - 调用 AI 服务并将流式结果推送前端窗口。
  - 提供截图/OCR/录屏能力（录屏包含 ffmpeg 检查与下载）。

## 3. 运行时模型

### 3.1 全局状态

- 后端以 `AppState` 为全局共享状态中心，承载：
  - 设置快照（热键、功能开关、AI 配置、录屏参数）。
  - 窗口可见状态与回填流程状态。
  - 文本/图片管理器实例。
  - 录屏运行时状态。

### 3.2 通信模型

- 前端 -> 后端：`invoke(command)`，统一封装在 `src/services/ipc.js`。
- 后端 -> 前端：`emit(event, payload)`，用于实时同步：
  - 剪贴板历史变化。
  - 录屏状态与下载进度。
  - 快捷键冲突与设置导航。
  - AI 流式输出窗口更新。

## 4. 核心链路概览

### 4.1 文字/图片剪贴板

1. 系统剪贴板变化触发 wake 事件。
2. 文本监听器与图片监听器各自消费事件并写入管理器。
3. 仅在窗口可见时推送增量/全量 payload；不可见时打脏标记，待下次显示同步。
4. 回填时先隐藏窗口，再写回系统剪贴板并模拟粘贴。

### 4.2 划词 AI

1. Windows 低级键鼠 Hook 监听拖拽/双击选词动作。
2. 通过 `Ctrl+C` 捕获选中文本并恢复原剪贴板。
3. 弹出 `selection_toolbar`，用户触发翻译/解释。
4. 后端发起 AI 流式请求，持续更新 `result_display` 窗口。

### 4.3 截图与 OCR

1. 截图快捷键/命令触发全屏捕获并显示 `screenshot` 窗口。
2. 前端框选后可保存、固定图片、或触发 OCR。
3. OCR 结果以独立文本窗口展示。

### 4.4 录屏

1. 开启录屏前检查 `ffmpeg.exe`（缺失则按需下载）。
2. 视频由 ffmpeg 采集桌面；音频由原生 WASAPI 录制为 wav。
3. 停止时将音频与视频合并，输出最终文件并广播状态。
4. 录屏胶囊支持快捷键唤起、紧凑/展开尺寸切换。
